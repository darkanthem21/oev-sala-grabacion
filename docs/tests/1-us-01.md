# Documentación de Pruebas: US-01 - Inicio de sesion

**Historia de Usuario**
> **Como** usuario solicitante registrado,
<br>
> **Quiero** iniciar sesión en la plataforma usando mi correo electrónico y contraseña,
<br>
> **Para** acceder de forma segura a mi cuenta y gestionar mis reservas y solicitudes.

**Criterios de Aceptación (AC)**
- [X] AC1 - Página debe mostrar formulario con campos "Correo electrónico" y "Contraseña", con un botón "Iniciar sesión".
- [X] AC2 - El campo de contraseña debe ocultar caracteres ingresados con asteriscos (***) o puntos (●●●).
- [X] AC3 - Si las credenciales son correctas, el sistema debe redirigir al usuario al panel principal de reservas.
- [X] AC4 - Si el correo o la contraseña son incorrectos, el sistema debe mostrar un mensaje de error genérico.
- [X] AC5 - El sistema debe bloquear temporalmente la cuenta después de 5 intentos fallidos consecutivos por motivos de seguridad.
- [X] AC6 - Se ofrece la posibilidad de solicitar un cambio de contraseña.

---

**Enfoque en los Criterios de Aceptación para Casos de Prueba Manuales**

**AC1: Formulario básico de ingreso**

* **Pruebas a redactar:** 1
* **Enfoque:** Verificación visual (UI). Comprobar que los campos de "Correo electrónico", "Contraseña" y el botón "Iniciar sesión" se rendericen correctamente.

**AC2: Ocultamiento de contraseña**

* **Pruebas a redactar:** 1
* **Enfoque:** Verificación de privacidad. Ingresar texto y validar que los caracteres se enmascaren visualmente (asteriscos/puntos).

**AC3: Redirección con credenciales correctas**

* **Pruebas a redactar:** 1
* **Enfoque:** Ruta feliz (Happy path). Ingresar credenciales válidas y comprobar el acceso exitoso y redirección al panel principal de reservas.

**AC4: Mensaje de error genérico ante fallo**

* **Pruebas a redactar:** 3
* **Enfoque:** Seguridad y rutas negativas. Probar combinaciones de error (correo erróneo/clave correcta, correo correcto/clave errónea, ambos erróneos) asegurando que el mensaje sea siempre idéntico y no filtre qué dato específico falló.

**AC5: Bloqueo tras 5 intentos fallidos**

* **Pruebas a redactar:** 2
* **Enfoque:** Límite de estado y temporalidad.
  1) Agotar los 5 intentos con credenciales inválidas y verificar la inhabilitación del acceso.
  2) Validar que el bloqueo se levanta automáticamente al transcurrir el tiempo configurado.

**AC6: Solicitud de cambio de contraseña**

* **Pruebas a redactar:** 4
* **Enfoque:** Ciclo de vida, integración y seguridad.
  1) Ruta feliz (solicitud exitosa verificando la salida del correo en consola).
  2) Entradas inválidas (intentar recuperar un correo no registrado).
  3) Seguridad de arquitectura (alteración manual del token en la URL).
  4) Expiración (intentar usar el enlace firmado fuera de plazo o duplicado).

**Caso de Prueba [AC5-001]: Bloqueo temporal tras agotar 5 intentos fallidos** 
* **Ruta Implementación:** `src/personas/tests/test_seguridad.py`
* **Verificador Responsable:** QA / Desarrollador
* **Rol del Actor:** Usuario solicitante registrado
* **Datos de Prueba (Test Data):**
  * Correo: `solicitante.bloqueo@uach.cl`
  * Contraseñas: Varias contraseñas incorrectas.

* **1. Setup (Precondiciones):**
* [ ] Cuenta válida existente, actualmente sin bloqueos.
* [ ] El parámetro de intentos máximos en el módulo de configuración está definido en 5.
* [ ] Página de inicio de sesión abierta.

* **2. Ejecución (Pasos a seguir):**
* [ ] Ingresar el correo correcto y una contraseña incorrecta; hacer clic en "Iniciar sesión". Repetir esto 4 veces.
* [ ] En el quinto (5to) intento, volver a ingresar una clave incorrecta y enviar el formulario.

* **3. Verificación (Resultado Esperado / Oráculo):**
* [ ] Tras el 5to intento fallido, el sistema deniega el acceso y el mensaje de error notifica que la cuenta ha sido bloqueada temporalmente por haber superado el límite de intentos (indicando la duración del bloqueo si aplica).

* **4. Teardown (Postcondiciones/Limpieza):**
* [ ] Mantener el estado bloqueado para el siguiente caso de prueba (AC5-002), o desbloquear manualmente por base de datos si es una ejecución aislada.

* [ ] El sistema retira la penalización de bloqueo, autentica al usuario correctamente y lo redirige al panel principal.

* **Rol del Actor:** Usuario solicitante
